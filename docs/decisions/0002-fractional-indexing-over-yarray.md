# 0002. Order cards with fractional indexing, not `Y.Array`

- **Status:** Accepted
- **Date:** 2026-11-19

## Context

The natural Yjs model is a `Y.Array` of cards per column. Moving a card in a `Y.Array` is a delete
plus an insert. If two users move the same card concurrently, both inserts survive and the card is
duplicated.

## Decision

Store cards in a flat `Y.Map<cardId, Y.Map>`. Each card holds `columnId` and `position`, a
fractional-index string generated by the `fractional-indexing` library. Moving a card updates only
these two fields inside one transaction. The UI sorts by `position` (lexicographic) and breaks ties
by `id`. Columns follow the same scheme.

## Consequences

- Concurrent moves resolve with per-field last-writer-wins: no duplicates, no lost cards.
- Two clients can generate the same position concurrently; the `id` tie-breaker keeps ordering
  deterministic.
- Position strings grow slowly under repeated inserts at the same spot; acceptable for board sizes.
