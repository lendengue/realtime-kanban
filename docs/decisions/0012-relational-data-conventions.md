# 0012. Relational data conventions

- **Status:** Accepted
- **Date:** 2026-11-19

## Context

The spec lists the tables and asks for UUID v7 ids, `citext` e-mails, Drizzle and Postgres 17+.
The driver, how ids are generated and when each table is created were open.

## Decision

- **Drizzle ORM 0.45** (latest stable; 1.0 is still a release candidate) with the `pg` driver
  (MIT). `postgres` (postgres.js) was not chosen because of its Unlicense terms (see ADR 0007).
- **UUID v7** primary keys generated by Postgres 18's native `uuidv7()` default, so every insert
  path (API, seed, collab) gets time-ordered ids without application code.
- **`citext`** is enabled by a hand-written first migration (`0000_extensions.sql`) because
  drizzle-kit does not emit `CREATE EXTENSION`.
- Migrations are generated with drizzle-kit and applied by our own runner (`runMigrations`), which
  the CLI (`pnpm db:migrate`) and the Testcontainers setup share.
- Tables are introduced by the phase that uses them: `board_snapshots` (phase 4) and
  `activity_events` (extra) are not created yet. Creating a board does not yet create its initial
  Y.Doc with default columns; that arrives with `packages/board-doc` in phase 2.
- Timestamps are `timestamptz`; the API serialises them as ISO 8601 strings.

## Consequences

- Postgres 18 is required (no `uuidv7()` before it); the spec's "17+" minimum is raised to 18.
